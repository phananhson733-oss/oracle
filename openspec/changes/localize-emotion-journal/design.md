# Design: 情绪日记本土化

## 架构决策

### D1: 情绪模型扩展

**问题**：当前 4 种情绪太少，但无限扩展会增加选择困难。

**决策**：采用 3 层情绪模型：
- **一级**：4 个情绪色调（暖/冷/重/轻）用颜色区分
- **二级**：12 个具体情绪词，每个归属一个色调
- 用户先感受色调（直觉），再选具体词（精确）

```
暖色调（--success 系）: 愉悦、感动、满足
冷色调（--info 系）:    平静、释然、期待
重色调（--danger 系）:  委屈、愤怒、焦虑
轻色调（--warning 系）: 无力、孤独、迷茫
```

**理由**：
- 比 4 个选项丰富，但不至于 20+ 选项造成决策疲劳
- 色调分组让选择更直觉化
- 12 个词覆盖中国年轻人高频情绪表达

### D2: 引导流程从 5 步精简为 3 步

**问题**：5 步 CBT 流程太长，用户容易中途放弃。

**决策**：核心 3 步 + 可选深入
1. **发生了什么？**（情境 + 情绪，合并）
2. **脑子里在想什么？**（自动思维 + Hot Thought，合并）
3. **换个角度呢？**（证据辩论 + 平衡思维，合并为引导式提问）

可选：完成 3 步后提供「想再聊聊吗？」入口，展开更深层的思维觉察。

**理由**：
- 3 步是用户注意力的舒适区
- CBT 的「证据辩论」和「平衡思维」本质上是一个动作
- 降低门槛 → 提升完成率 → 用户更愿意坚持记录

### D3: AI 分析输出格式

**问题**：当前 JSON 结构化输出需要前端逐字段渲染，且临床感太强。

**决策**：改为 Markdown 自然语言输出，前端直接渲染。

**输出结构**：
```
[共情段] 1-2 句，让用户感到被理解
[洞察段] 2-3 句，指出思维模式 + 星象关联
[行动段] 1-2 个具体建议
```

**理由**：
- 自然语言更有温度，像朋友在聊天
- 减少前端渲染复杂度
- Markdown 支持富文本（加粗、列表）足够展示

### D4: 数据兼容策略

**问题**：旧 CBTRecord 使用 `moods: [{ id, name, initialIntensity }]` 格式。

**决策**：后端保持 `moods` 数组格式不变，前端适配：
- 旧记录：单 mood 对象 → 正常渲染
- 新记录：多 mood 对象 → 渲染多个情绪标签
- `situation` 字段含义不变
- 新增的 `bodySignal` 为可选字段，旧记录缺失时不显示

**理由**：Redis 中的旧数据最多存活 3 个月，无需数据迁移，自然过期即可。
