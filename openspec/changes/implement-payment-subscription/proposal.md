# 付费与订阅系统实现（积分制优化）

## 概述

为 AstrologyWiki 引入订阅 + 积分（Points/Credits）双轨商业化。订阅维持核心权益；非订阅用户通过购买积分解锁付费功能。直接“单次购买/购买次数”将被积分购买替代。

## 背景

当前应用所有功能免费开放，缺乏可持续的商业模式。需要：
1. 建立用户账户体系（支持云端数据同步）
2. 实现付费订阅与积分充值
3. 设计合理的免费/付费边界
4. 开发高价值付费报告

## 变更范围

### 1. 用户账户体系
- 注册/登录（Google、Apple、Email）
- 用户数据云端存储与同步
- localStorage 数据迁移
- **首次注册赠送 7 天免费订阅体验**

### 2. 支付集成
- Stripe 订阅
- Stripe 积分充值（套餐）
- PayPal / 信用卡支付（与 Stripe 并行入口）
- 后续支持 Apple IAP / Google Play Billing

### 3. 权益系统
- 免费权益与订阅权益定义
- 积分余额（充值 + 消耗）
- 前端权益校验与付费墙
- 后端权益验证
- **购买记录缓存与唯一性校验**

### 4. 订阅服务
- 单档订阅：**$6.99/月**
- 订阅管理（开通、取消、续费）

### 5. 积分系统
- 积分购买、余额管理与消费扣减
- 积分解锁所有付费内容（永久/每日/每月/消耗型）
- 订阅赠送积分（默认 500，每次成功支付后发放，展示在权益列表）
- GM 命令用于发放/清零积分（开发测试）

### 6. 付费报告
- P0：年度运势报告、月运报告
- P1：合盘深度报告、事业/职业报告
- P2+：财富报告、土星回归、行运预测

## 积分与定价假设

- **基准：1 积分 = $0.10**
- 充值套餐与营销文案可配置（用于 A/B 测试与地区差异化）
- 价格保持原有美元档位时，积分向上取整（例如 $0.99 ≈ 10 积分）

## 核心付费点设计（积分制）

### 5.1 探索自我 (MePage)
| 功能 | 免费/付费 | 积分 |
|-----|----------|------|
| 快速浏览 Big 3 卡片 | 免费 | - |
| 技术规格卡片 | 免费 | - |
| 心理维度 - 前 2 个 (Emotions, Attachment) | 免费 | - |
| 心理维度 - 后 4 个 (Talents, Coping, Sabotage, Lessons) | 积分解锁 | 10/个（永久） |
| 核心主题内容 | 积分解锁 | 10/个（永久） |

### 5.2 今日运势 (TodayPage)
| 功能 | 免费/付费 | 积分 | 重置 |
|-----|----------|------|------|
| 公开内容 (4 维等) | 免费 | - | - |
| 展开详情页 - 阅读今日剧本 | 积分解锁 | 10 | 每日重置 |
| 星象详情 - 查看详情 | 积分解锁 | 10/次 | 每日重置 |

### 5.3 双人合盘 (UsPage)
| 功能 | 免费/付费 | 积分 | 说明 |
|-----|----------|------|------|
| 合盘解读 | 前 3 次免费 | 30/次 | 永久免费 3 次，之后积分解锁 |
| 合盘内查看详情 | 积分解锁 | 10/次 | 需唯一性校验 |

**合盘唯一性校验规则**：
- 基于双方出生信息生成唯一哈希
- 任一方的任何信息（包括姓名）有修改，视为新的合盘
- 防止通过修改信息免费刷合盘次数

### 5.4 Ask 问答 (AskOraclePage)
| 功能 | 免费/付费 | 积分 | 重置 |
|-----|----------|------|------|
| 问答 | 每周免费 3 次 | 20/次 | 每周重置 |

### 5.5 CBT 日记统计 (CalendarStats)
| 功能 | 免费/付费 | 积分 | 说明 |
|-----|----------|------|------|
| 日记记录 | 免费 | - | 永久免费 |
| 4 个统计卡片中的 3 个解读内容 | 积分解锁 | 20/月 | 按自然月计费 |

**UI 设计**：未解锁内容显示遮罩 + 锁图标

## 订阅权益设计

**定价：$6.99/月**

| 权益 | 订阅用户 | 免费用户 |
|-----|---------|---------|
| 7 天免费体验 | - | 首次注册赠送 |
| 所有"查看详情"按钮 | 免费 | 积分解锁 |
| Ask 问答 | 每周 5 次 (3免费+2权益) | 每周 3 次免费，超出积分解锁 |
| 探索自我付费内容 | 全部解锁 | 积分解锁 |
| 双人合盘 | 每周 5 次 (3免费+2权益) | 永久免费 3 次，超出积分解锁 |
| CBT 日记统计解读 | 全部解锁 | 积分解锁 |
| 订阅赠送积分 | +500 积分 | 每次成功支付发放 |
| 付费报告 | **8 折优惠（积分价格）** | 原价（积分） |

**注意**：
- 合盘次数显示为 "5/5"（含免费 3 次 + 权益 2 次）
- 权益次数每周重置
- 订阅用户进入 CBT 日记统计后自动解锁
- 报告购买必须使用积分，订阅用户按折扣积分计费

## 缓存策略

### 前端缓存原则
1. **数据无变化不重复加载**：已加载的页面数据缓存到内存/localStorage
2. **购买记录缓存**：已购买的内容记录到本地，避免重复请求后端
3. **积分余额缓存**：积分余额短 TTL 缓存（支付成功后强制刷新）
4. **唯一性哈希缓存**：合盘等需要唯一性校验的内容，缓存哈希值用于快速比对

### 缓存失效策略
1. 用户主动修改数据时失效
2. 订阅状态变更时失效
3. 支付成功或积分消费时立即刷新
4. 设置合理的 TTL（如每日运势 24 小时后失效）

## 影响分析

| 领域 | 影响 |
|-----|------|
| 前端 | 新增登录 UI、付费墙、订阅管理页、积分余额展示、锁标识 UI |
| 后端 | 新增用户服务、支付服务、权益服务、积分充值/消费服务、唯一性校验服务 |
| 数据库 | 新增 users、subscriptions、purchase_records、free_usage、subscription_usage、synastry_records 表（含积分记录） |
| 第三方 | Stripe、PayPal、Google OAuth、Apple Sign In |

## 成功指标

- 注册转化率 > 30%
- 付费转化率 > 5%
- 订阅用户月留存 > 70%
- 积分复购率 > 20%

## 风险与缓解

| 风险 | 缓解措施 |
|-----|---------|
| AI Token 成本超支 | 保守定价（80%毛利）+ 用量监控 |
| 订阅取消率高 | 订阅专属内容 + 取消挽留流程 |
| 支付失败 | Stripe 自动重试 + 失败通知 |
| 积分滥用 | 设备指纹 + IP 限制 + 唯一性校验 |
| 合盘次数被刷 | 严格的唯一性哈希校验 |
