# 提案：优化星座配对解读报告

## 变更 ID
`enhance-pairing-report`

## 动机
当前「发现 > 星座配对」功能存在以下问题：
1. **报告以弹窗形式展示**，空间狭小，无法承载丰富内容
2. **解读内容过于简单**——仅靠前端硬编码的分数 + 两段固定模板文字，缺乏个性化和深度
3. **无后续交互**——用户看完只能关闭，没有提问或深度探索的入口

用户期望参考「双人合盘」的报告体验：全屏展示、内容丰富、可互动。

## 目标
- 将配对报告从弹窗改为**全屏页面**展示，参考 synastry 的 step=2 模式
- 引入**后端 AI 生成**的个性化解读内容，替换前端硬编码文本
- 增加**提问入口**，用户可就配对结果进行追问

## 现状分析

### 当前实现（pairing 页面）
| 维度 | 现状 |
|------|------|
| 报告展示 | 弹窗覆盖层（overlay） |
| 计算方式 | 纯前端静态规则（硬编码匹配表 + 加减分） |
| 内容深度 | 总分 + 4 维度分数 + 1 段模板文字 + 固定相处指引 |
| 用户交互 | 仅关闭/确认按钮 |
| 输入数据 | 星座 + 生肖 |

### 参考目标（synastry 页面）
| 维度 | 实现 |
|------|------|
| 报告展示 | 全屏页面 + Tab 导航 |
| 计算方式 | 后端 AI 生成 + 星历计算 |
| 内容深度 | 多 Tab 维度、卡片化内容、深度解读 Overlay |
| 用户交互 | Tab 切换、卡片点击深度解读、丰富的内容层次 |

## 设计方案

### 能力 1：全屏报告页面（前端）

将 pairing 页面改为 step 双步模式：
- **Step 1**（现有）：星座 + 生肖选择输入界面
- **Step 2**（新增）：全屏报告展示页面

报告页面结构：
1. **顶部**：双方星座 + 生肖信息展示、契合度总分
2. **维度分析区**：卡片化展示多个维度（扩展为 6 个维度：情感共鸣、性格互补、沟通默契、长期潜力、生活节奏、价值观）
3. **综合解读区**：AI 生成的个性化分析文字（2-3 段）
4. **相处建议区**：具体可操作的建议（AI 生成）
5. **提问入口**：底部固定按钮「有疑问？问一问」，跳转到 ask 页面并携带配对上下文

### 能力 2：后端 AI 配对分析接口（后端）

新增 API 端点 `POST /api/pairing`：
- **输入**：甲方星座+生肖、乙方星座+生肖
- **输出**：AI 生成的配对分析 JSON（总分、各维度评分+解读、综合分析、相处建议）
- **Prompt 设计**：在 `backend/src/prompts/templates/` 下新增 `pairing/` 模块
  - 融合西方占星元素相性（火/土/风/水）+ 中国生肖三合六合
  - 结合心理学视角（依恋理论、沟通模式）
  - 输出风格：现代、年轻化，避免玄学化
- **缓存策略**：相同星座+生肖组合可缓存结果（组合有限，12×12×12×12 = 20736 种）

### 能力 3：配对追问功能（前端+后端）

在报告页面底部提供「有疑问？问一问」按钮：
- 跳转到现有的 ask 页面
- 自动携带配对上下文（双方星座、生肖、分析摘要）
- ask 页面基于上下文生成针对性的引导问题

## 不包含的内容
- 不涉及星盘图表渲染（配对功能仅基于星座+生肖，无需完整出生信息）
- 不涉及 synastry 的 Tab 多视角切换（配对是轻量级功能，单页即可）
- 不涉及支付/会员体系
- 不涉及用户档案管理

## 风险与注意事项
- AI 生成内容的首次加载速度——需添加 loading 骨架屏
- 缓存策略需合理设计，避免内容千篇一律又避免每次都调 AI
- 配对功能定位为「轻量级趣味功能」，不应过度复杂化
