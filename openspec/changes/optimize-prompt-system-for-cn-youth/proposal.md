# 提案：优化 Prompt 系统，面向中国年轻用户

## 变更 ID
`optimize-prompt-system-for-cn-youth`

## 背景

AstrologyWiki（星智）定位为面向中国大陆 18-35 岁年轻人的占星应用。现有 Prompt 系统虽已建立三层架构（core/cultural/templates），且 cultural 层已包含场景库、比喻库等本土化内容，但存在以下核心问题：

### 问题 1：本土化深度不足

**现状**：
- cultural 层已有接地气的场景库（催婚、996、刷手机等）和行星比喻，但**模板层对 cultural 层的利用不统一**
  - 部分模板（如 daily/forecast.ts）直接引用 `DEFAULT_PERSONA` + `TONE_GUIDE`
  - 部分模板（如 natal/overview.ts）已移除引用，直接内嵌角色定义
  - 导致不同模块的输出风格可能不一致
- 缺少中国传统文化元素的融合：五行与星座的对应关系、二十四节气与行运的结合、生肖与星盘的互参
- 语言风格整体偏「心理咨询师」，不够贴近年轻人社交媒体（小红书/朋友圈/B站弹幕）的表达习惯

**期望**：
- 融入中国传统文化元素，让占星不再是纯粹的「西方舶来品」
- 语言风格更年轻化：善用网络热梗（适度）、短句、emoji 风格文案
- 场景更贴近 Z 世代：搞钱、MBTI 对比、社恐 vs 社牛、摆烂 vs 内卷

### 问题 2：AI 内容生成效率

**现状**：
- 大部分 API 端点每次请求只做 1 次 AI 调用，是串行的
- 前端页面如 natal 有 overview/core-themes/dimension 三个内容块，需要用户分别等待
- annual-report 已实现 11 模块并行，但其他页面未跟进
- 无预生成/预缓存机制

**期望**：
- 所有多内容块页面支持并行生成
- 引入「种子上下文」机制保证并行生成内容的连贯性
- 考虑 SSE 流式返回，让用户看到内容逐步出现

### 问题 3：Prompt 架构碎片化

**现状**：
- 56 个 Prompt 模板，各自为政
- `BASE_SYSTEM` 提供了基础人格，但模板对 cultural 层的引用方式不统一（有的引用，有的内嵌）
- 跨模块无上下文共享：natal 分析的结论不会传递给 daily，导致同一用户在不同页面可能看到矛盾的解读
- 比喻库（metaphors）、场景库（scenarios）虽然存在，但大部分模板没有动态调用它们

**期望**：
- 统一的人格和知识库注入机制
- 跨模块上下文串联（natal → daily → ask）
- cultural 层资源被模板自动利用，而非手动拼接

## 涉及能力

1. **prompt-localization**：Prompt 内容本土化深度优化
2. **parallel-generation**：多内容块并行生成 + 一致性保障
3. **prompt-architecture**：Prompt 架构统一化重构

## 影响范围

- `backend/src/prompts/` — 所有层级
- `backend/src/services/ai.ts` — 并行调用、上下文传递
- `backend/src/api/*.ts` — API 路由适配并行模式
- 前端无需改动（API 响应格式不变）

## 成功标准

1. 用户反馈内容「更像中国人写的，不像翻译腔」
2. 多内容块页面的首屏加载时间降低 40%+（并行 vs 串行）
3. 同一用户在不同模块看到的内容保持一致性（不会出现矛盾）
4. 新增 Prompt 时无需手动拼接 cultural 层资源

## 风险与约束

- **渐进式执行**：三个能力按顺序实施，先架构重构，再本土化，最后并行优化
- **向后兼容**：API 响应格式保持不变，前端无感知
- **成本考量**：并行生成会增加 API 调用量，但用户表示性价比暂不考虑
- **内容审核**：融入传统文化元素时避免封建迷信倾向，保持心理学导向
